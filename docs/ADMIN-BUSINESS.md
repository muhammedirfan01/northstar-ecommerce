# Store settings, offers and sales

All `/api/admin` routes below use the existing signed-in administrator middleware and no-cache policy. JSON responses use `{success:true,data:...}`. Invalid fields return 400; stale versions return 409. No endpoint accepts or returns payment credentials.

* `GET /admin/settings`: `{settings, paymentConfigured}`. Settings contain `version`, `storeName`, optional `supportEmail`, `supportPhone`, `invoiceAddress`, `shippingChargePaise`, nullable `freeShippingAbovePaise`, `taxBasisPoints`, `codEnabled`, `onlineEnabled`. PATCH accepts the complete settings form plus version. Defaults preserve existing ₹50 delivery at merchandise subtotal ≤₹500, zero extra tax and both payment methods enabled. Online payment still requires server credentials. Store information is snapshotted for new invoices.
* `GET /admin/offers`: page/limit/search, status all/active/scheduled/expired/inactive, sort newest/name/expiry. Returns offers and pagination. `GET /admin/offers/targets?scope=all|product|category&search=...` searches up to 50 existing nondeleted targets, sorted by name.
* `POST /admin/offers`: name, description, scope all/product/category, nullable targetId, discountType percentage/fixed, discountValue (integer percent or integer paise **per unit**), startDate, expiryDate, isActive. PATCH `/admin/offers/:id` takes the same fields plus version. PATCH `/admin/offers/:id/status` takes version and isActive. Disable campaigns to retire them; historical orders retain snapshots.
* Automatic offers apply only to new checkout quotes/orders, not catalog display prices. For each line, the best eligible campaign wins; ties use campaign ID. Category campaigns include direct children. Fixed discounts are per unit, capped at its price. Coupons apply after offers; coupon minimum spend uses that remaining amount. Delivery thresholds use original merchandise subtotal. Extra tax uses discounted merchandise, rounded to nearest paise, excluding delivery. Existing base prices are retained for atomic inventory checks. Campaign settings are read inside the order transaction, and the expected total must match. Existing order/payment retries reuse the saved order.
* `GET /admin/reports/sales`: from/to inclusive YYYY-MM-DD in Asia/Kolkata, at most 366 days; group day/month, page/limit/search/status/paymentStatus/sort (same order filters/sorts as the order directory). Defaults last 30 days. Returns summary, trend, orders and pagination. `/export` returns all matching orders as UTF-8 CSV with formula-safe escaping, using the same filters and sort.
* Sales is a placement-date cohort with current states, not a cash-flow ledger: collected sums paid/refunded orders; completed refunds sum their recorded refund amount; net is their difference. Pending and failed payments do not count as collected. Empty periods have zero totals. Order list and export include completed-refund values. No synthetic sales, stock or customer records are created.
